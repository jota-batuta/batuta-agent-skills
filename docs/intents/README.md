# Intent capture records

Persisted records of operator-confirmed intents per the `intent-capture` skill (v4.3+).

## What lives here

Every confirmed intent (`status: "confirmed"`) generated by `intent-capture` Step 5 is persisted as a markdown file:

- **Filename**: `<YYYY-MM-DD>-<id>-<slug>.md` (e.g. `2026-05-04-IC-003-auto-injection-routing-persistence.md`)
- **Format**: YAML frontmatter (lifecycle metadata) + narrative body (context, decisions, related artifacts) + the original JSON intent in a fenced code block at the end

Intents that never reached `confirmed` status (rejected, draft, ready_for_confirmation that timed out) are NOT archived here — they are transient.

## Why

- **Audit trail**: every concrete change in the project starts with a confirmed intent. Persisted records make the chain `intent → plan → PR → merge → vault L2` traceable.
- **Context for future sessions**: when the next session starts, recent intents inform what is in flight, what was rejected and why, and what acceptance criteria were set.
- **ADR adjacency**: ADRs answer "why this decision". Intents answer "what does the operator want and how was it scoped". Both are first-class development artifacts.

## Format

Each file follows this template:

```markdown
---
id: IC-NNN
status: confirmed
captured_at: YYYY-MM-DD
confirmed_at: YYYY-MM-DD
operator_id: <github-handle>
agent_version: <model-id>
category: feature | bug | refactor | research | meta
related_pr: <PR-number-or-TBD>
related_branch: <branch-name>
related_plan: <path-or-empty>
---

# IC-NNN — <one-line summary>

## Original ask

> "Verbatim quote of the operator's first message that triggered intent-capture"

## Refined intent

The full refined description after grilling.

## Scope

### In
- bullet list of in-scope files/changes

### Out
- bullet list of explicit non-goals

## Acceptance

- bulleted criteria

## Routing declaration

| Trabajo | Quién | Por qué |
|---|---|---|
| <file> | Subagent (X) / Main-direct | <reason> |

## Outcome

What shipped, where (PR link), follow-ups.

## Original JSON

\`\`\`json
{ ... full intent JSON ... }
\`\`\`
```

## Lifecycle

1. Operator describes work → agent runs `intent-capture` (Steps 1–4: Detect → Grill → Capture → Present).
2. Operator confirms ("dale", "procedé", "yes, go ahead").
3. Step 5 writes BOTH:
   - `<project-root>/.claude/.intent-confirmed-<ISO>` — empty audit token (gitignored), valid until next operator turn (consumed by `pre-edit-intent-gate.sh`).
   - `docs/intents/<YYYY-MM-DD>-<id>-<slug>.md` — versioned record, lives forever in git history.
4. Step 6 declares routing and waits for operator approval.
5. PRs that result from the intent reference the IC-NNN ID in their description.
6. Session journals (`docs/sessions/`) link to the recent intents.

## Numbering

IC-NNN is monotonically increasing across the project (not per-session, not per-feature). Find the highest existing number under `docs/intents/` and add 1. Reserved gaps are allowed if an intent was ID'd but never confirmed.
